# AutoLoc API

REST API for a car-rental agency, built step by step during the ASI workshops (Esprit, 2026-27).
It manages agencies, employees, vehicles, equipment, clients, reservations, contracts, payments and maintenance.

| | |
|---|---|
| Language / build | Java 17, Maven |
| Framework | Spring Boot 3.3.5 (Web, Data JPA, Validation, DevTools) |
| Database | MySQL (tested with the MariaDB bundled in XAMPP) |
| Tools | Lombok, SpringDoc OpenAPI 2.6.0 (Swagger UI), Postman |
| Group / artifact | `tn.esprit.autoloc` / `autoloc-api` |

## 1. Architecture

The code is split into layers. Each layer depends only on the interface of the layer below it.

```
Postman / Swagger UI
        |  HTTP + JSON
        v
web.controller   REST controllers + GlobalExceptionHandler      (Atelier 5)
        |
        v
service          I...Service / ...ServiceImpl: business rules   (Atelier 4)
        |
        v
repository       I...Repository (Spring Data JPA)               (Atelier 3)
        |
        v
domain           JPA entities and enums                         (Ateliers 1-2)
        |
        v
MySQL database `autoloc_db`
```

```
src/main/java/tn/esprit/autoloc
├── AutolocApiApplication.java
├── domain/        9 entities + 5 enums
├── repository/    9 interfaces extending JpaRepository<Entity, Long>
├── service/       9 interfaces + 9 implementations + ValidationUtils
├── exception/     ResourceNotFoundException
├── web/
│   └── controller/   9 controllers, GlobalExceptionHandler, OpenApiConfig
└── demo/          optional CascadeDemoRunner (profile "demo")
docs/              workshop notes and the Postman collection
```

## 2. Domain model

Nine entities. Foreign keys are generated by Hibernate with its default names (for example `agence_id_agence`).

| Association | Owner side (holds the foreign key) | Cascade | Fetch |
|---|---|---|---|
| Agence → Vehicule | Vehicule | none | LAZY |
| Agence → Employe | Employe | none | LAZY |
| Vehicule ↔ Equipement | Vehicule (join table `vehicule_equipement`, a `Set`) | none | LAZY |
| Client → Reservation | Reservation | PERSIST | LAZY |
| Reservation → Vehicule | Reservation | none | LAZY |
| Reservation ↔ Contrat (one-to-one) | Contrat | ALL (from Reservation) | LAZY |
| Vehicule → Maintenance | Maintenance | PERSIST | LAZY |
| Contrat → Paiement | Paiement | ALL + `orphanRemoval` | LAZY |

`Contrat → Paiement` is a composition: a payment only exists through its contract. Deleting a contract
deletes its payments, and removing a payment from the contract's list deletes it in the database.
The reasoning for each choice is in `docs/fetch-strategy.md`.

Enums: `StatutVehicule`, `CategorieVehicule`, `RoleEmploye`, `StatutReservation`, `ModePaiement` (stored as text).

## 3. Getting started

### Requirements

- JDK 17 and IntelliJ IDEA (Maven is built in; an internet connection is needed for the first import)
- MySQL running on `localhost:3306` (for example XAMPP's MySQL module)
- Postman (optional, for testing)

### Configuration

`src/main/resources/application.properties`:

| Property | Value | Note |
|---|---|---|
| `spring.datasource.url` | `jdbc:mysql://localhost:3306/autoloc_db?createDatabaseIfNotExist=true` | the database is created automatically |
| `spring.datasource.username` | `root` | |
| `spring.datasource.password` | `${DB_PASSWORD:}` | read from the `DB_PASSWORD` environment variable; empty by default (XAMPP) |
| `spring.jpa.hibernate.ddl-auto` | `update` | development only; tables are created from the entities |
| `server.servlet.context-path` | `/api` | prefix of every URL |
| `spring.jackson.serialization.fail-on-empty-beans` | `false` | temporary, removed when DTOs are introduced |

If your MySQL `root` user has a password, set `DB_PASSWORD` in IntelliJ under
Run → Edit Configurations → Environment variables.

### Run

1. Start MySQL.
2. Open the project in IntelliJ and enable annotation processing for Lombok
   (Settings → Build, Execution, Deployment → Compiler → Annotation Processors).
3. Run `AutolocApiApplication`.
4. Check the console for `Found 9 JPA repository interfaces` and `Started AutolocApiApplication`.
5. Check the database: `USE autoloc_db; SHOW TABLES;` should list 10 tables (9 entities + `vehicule_equipement`).

## 4. API

Base URL: `http://localhost:8080/api`

| Resource | Route | Operations |
|---|---|---|
| Agencies | `/agences` | list, get, create, update, delete |
| Employees | `/employes` | list, get, create, update, delete |
| Vehicles | `/vehicules` | list, get, create, update, delete |
| Equipment | `/equipements` | list, get, create, update, delete |
| Clients | `/clients` | list, get, create, update, delete |
| Reservations | `/reservations` | list, get, create, update, delete |
| Contracts | `/contrats` | list, get, create, update, delete |
| Payments | `/paiements` | list and get only (read-only) |
| Maintenance | `/maintenances` | list, get, create, update, delete |

| Operation | Verb and route | Success | Errors |
|---|---|---|---|
| List | `GET /{resource}` | 200 | — |
| Get | `GET /{resource}/{id}` | 200 | 404 |
| Create | `POST /{resource}` | 201 | 400 |
| Update | `PUT /{resource}/{id}` | 200 | 404, 400 |
| Delete | `DELETE /{resource}/{id}` | 204 | 404 |

Errors share one JSON shape:

```json
{ "statut": 404, "message": "Contrat introuvable avec l'identifiant 9999", "horodatage": "2026-11-02T10:15:42" }
```

Linking objects: send the linked object with its id, for example a reservation with
`"client": {"idClient": 1}` and `"vehicule": {"idVehicule": 1}`. A contract can be created together with its payments:

```json
{ "dateSignature": "2026-11-02", "montantTotal": 480.00, "valide": true,
  "paiements": [
    { "montant": 150.00, "datePaiement": "2026-11-02", "modePaiement": "CARTE" },
    { "montant": 330.00, "datePaiement": "2026-11-06", "modePaiement": "VIREMENT" } ] }
```

### Business rules (service layer)

Violations return 400.

- A new object must not have an id.
- Required fields must be present (and not blank for text).
- Prices and amounts (`tarifJournalier`, `montantTotal`) must not be negative.
- A reservation's end date cannot be before its start date; same for a maintenance's end date.
- On update, links (agency, client, vehicle...) change only if they are sent; the equipment list and contract payments are not touched.

### Documentation and tests

- Swagger UI: `http://localhost:8080/api/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/api/v3/api-docs`
- Postman: import `docs/postman/AutoLoc.postman_collection.json` and `docs/postman/local.postman_environment.json`,
  select the `local` environment, then run the collection (73 tests: happy paths, 404, 400, 405, and the
  cascade scenario). The `Nettoyage` folder runs last and removes the test data.
- Optional demo: run the app with `-Dspring.profiles.active=demo` to see cascade, `orphanRemoval` and
  LAZY loading in the logs (`demo/CascadeDemoRunner`).

## 6. Known limitations

- Controllers expose the JPA entities directly (a deliberate, temporary choice); DTOs and validation annotations come later.
- There is no authentication and there are no automated tests; testing is done with Postman.
- `ddl-auto=update` is for development only. A production setup would use a migration tool.
- With XAMPP's MariaDB, Hibernate logs a warning about the unsupported "5.5.5" MySQL dialect. It is harmless here.

## 7. Troubleshooting

| Problem | Likely cause |
|---|---|
| `Communications link failure` | MySQL is not running or the port is not 3306 |
| `Access denied for user 'root'` | wrong password: set `DB_PASSWORD` |
| Red errors on getters in the IDE | Lombok plugin or annotation processing is off |
| 404 on `/contrats` | missing `/api` prefix in the URL |
| 415 in Postman | `Content-Type: application/json` missing |
| Swagger page fails to load | SpringDoc version does not match Spring Boot 3.3.x (this project uses 2.6.0) |
